# GPT Image 生图与改图

通过 `generate_gpt_image` 生成新图，通过 `edit_gpt_image` 修改现有图片。

## 何时使用

在用户明确要求创建新图像时使用，包括但不限于：

- “画一张……”“生成图片……”“做一张海报/头像/壁纸”
- 将文字描述视觉化
- 根据对话中已经明确的要求制作图像

用户要求修改、重绘、润色、换风格、增删元素或调整现有图片时，使用
`edit_gpt_image`。它会按顺序自动选取引用消息里的图片、当前消息里的图片，或本会话
上一张由插件生成的图片。不要把改图请求错误地交给 `generate_gpt_image`。

以下情况不要调用：

- 用户只是让你分析、描述或识别现有图片
- 用户要搜索互联网上已有的图片
- 用户只询问提示词、绘画方法或模型能力
- 用户没有表达生成图片的意图

## 调用规则

1. 用户的主题和主要限制已经明确时，直接调用，不要再次确认。
2. 只有缺少会彻底改变结果的关键信息时才简短询问；普通细节由你合理补全。
3. 每个用户请求默认只调用一次。用户明确要求多个独立版本时，才逐个生成。
4. 只把与用户讨论后形成的最终请求透传给工具，尽量保留用户原话、专有名词、作品角色/载具/场景名称、原作约束、精确文字和排除项。不要在 AstrBot 主模型侧扩写成视觉提示词、替换角色或自行补充剧情；Codex 会在联网检索后完成扩写和最终生图/改图。
5. 工具返回 `accepted` 代表后台任务已经受理，不代表图片已经生成。成品稍后会自动发送到当前聊天；此时只需告知“已开始生成/修改”，不要重复调用，也不要提前声称完成。
6. 每次生图或改图都必须让 Codex 先联网搜索至少 3 个相关、独立的参考来源，再由 Codex 扩写并生成；不要凭空编造现实世界的视觉细节。
7. 如果改的是本会话之前由 Codex 生成的图片，优先使用 `edit_gpt_image`，插件会继续该图片对应的 Codex session。
8. 不要在回复或工具结果中输出 Base64、服务器文件路径、API Key 或内部接口地址。
9. 工具失败时如实说明返回的错误，不要声称图片已经生成，也不要在同一轮无限重试。网络瞬时错误最多重试一次。

## 透传边界

主模型只负责把用户确认后的请求原样传给工具。不要替 Codex 编写主体、镜头、风格、灯光、材质等视觉扩写；尤其不要改写作品中的人物、载具、场景、物件名称或其原作属性。Codex 会联网查找参考、处理冲突、补齐视觉细节并执行最终生成。

## 示例

用户：画一张雨夜里的机械猫。

调用：

```text
generate_gpt_image(
  prompt="画一张雨夜里的机械猫。"
)
```

工具成功后：

```text
已开始生成，完成后会自动发出来。
```

用户：把我引用的这张图改成雪夜，人物和构图保持不变。

调用：

```text
edit_gpt_image(
  prompt="把目标图片的环境改成飘雪的冬季夜晚，加入自然积雪和冷色月光；严格保留人物身份、面部、服装、姿势、镜头视角和原始构图，不添加文字。"
)
```
